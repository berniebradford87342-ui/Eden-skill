# Eden 选题研究

先从用户本地配置读取环境变量 `EDEN_VAULT`（Obsidian vault根目录），`<EDEN_VAULT>`是占位符而非实际目录。未配置时询问vault位置，不假定本机路径。

每轮先读定位真源：
`<EDEN_VAULT>/Eden账号运营/AI青少年教育账号说明.md`。
读取失败时明确版本缺口，不另造定位。本项目主受众为普通家长，优先6—9年级；内容帮助听懂AI变化、看见可能、形成判断，不要求每条都变成工具教程。

## 两条选题路径

两条线固定命名为 **AI育儿热点话题** 与 **宝妈科普型**，分开建卡、统一按Eden定位评估。“宝妈科普型”不排除爸爸。每轮必须读 [全量评分规则](references/scoring.md) 与 [召回及来源核验](references/recall-and-provenance.md)。做三个月验证、扩展对标或基础知识转译时，再读 [三个月验证与基础内容](references/history-and-foundation.md)。当前对标分工与来源以Obsidian `Eden账号运营/对标账号库/00_对标账号库.md`及关联账号页为准；项目旧对标文档仅作历史研究。每轮必读[选题库与字段契约](references/obsidian-library.md)，并读取本轮关联卡片中的用户选择和复盘。

基础线：**对标真实知识点 → 原始资料核对 → 家长能理解的场景/判断 → 可兑现的解释或演示 → 待人工选择**。不要求每条当月热门；新场景是策划假设，不继承原作热度为家长需求证据。

## 原题先保留，讲法再适配

研究阶段的主标题逐字保留真实原题，另列“Eden怎么讲”，不把育儿化改写覆盖原题。技术小白科普本身可服务家长；标题不用出现宝妈、孩子、育儿，也不强行添加亲子案例。适配通过解释深度、信息取舍、例子及观众收获判断。

把“题目值得研究”“Eden适合讲”“目前能制作”分开。免费、收入、提分、一招解决等原题承诺未核实时，保留原题和候选身份，标出未核实的具体承诺；不等于允许照搬承诺发布，也不因准备不足取消整条。原题中署名、经历、5分钟等不自动变成Eden承诺。内容选定后才讨论最终标题。

同题不同作者可保留为备用原题/证据，但不重复凑独立选题数。广告原作不自动排除其真实问题，商业表现不能当自然需求证明；AI仅是生成手段且无相关知识价值的作品留素材池并说明理由，不硬改救题。

## 热点主链路

根据用户最新要求更新PPT流程：**第三方榜单打底＋对标真实原题＋B站/YouTube补充 → 核验去重 → 明确每条内容方案 → 七维评分排序 → 全量展示（至少15条有来源的评分候选） → 用户选择后入正式选题库**。推荐前5仅作附加视图，不能代替全量结果。

- 先读 [实跑流程](references/runbook.md)，需要覆盖/评分细则时读 [工作流程](references/workflow.md)。工具状态见 [数据源实测](references/source-audit.md)。
- 以真实原作品的问题和内容承诺为起点。AI只负责发现、核对、合并、解释适配；不能先想标题再找证据。
- 榜单是发现入口。大类热度不能替代家长相关性；同时用实际对标的问题词查漏。原题、正文、受众、AI实质关联、年龄/商业条件一起看。
- 每条卡写清：真实原题及链接 → 来源表现 → 家长能理解/判断什么 → Eden可保留的核心 → 待补证。热点线若必须换核心需求，降为素材；基础线允许保留知识机制后重建家长场景，必须标注新场景待验证。家长化不要求新增育儿标题或亲子场景；两条线都不能虚构孩子经历。
- 区分“内容方案已明确”“证据已核验”和“已经可制作”。至少15条评分候选的目标通过补研究满足，不拆重复话题或编造来源。低分、错配、待补证全部展示；只有题名无内容方案的仍展示但暂不打总分。来源确实不足时报告实际数和缺口。
- 作品ID、底层事件和话题分别去重；同一讲座转载、同一活动多条作品不冒充独立趋势。不同源、不同更新时间的指标分存，不相减当增长。
- 原平台评论只作具体问题证据，不凭昵称判断身份；AI自动总结、读者提示词不等于作者实测或逐字稿。

## 可重复的执行资源

- `scripts/collect_redfox.py --plan <计划.json> --out <新批次目录/采集>`：按保存的查询计划逐项调用，已有文件跳过；密钥经环境变量或隐藏交互输入，原始响应保留。只使用已核验的redfox.hk接口。
- `scripts/normalize_run.py <批次目录>`：将`采集/`、`curl实测/`和可选`ui_observations.json`规范化为来源、快照及覆盖统计；不自动做适配判断。
- `scripts/history_audit.py --config <audit-config.json> --out <审计目录>`：复用月榜和分段历史作品，输出三期增长矩阵、窗口覆盖及证据；不把缺榜补零。配置示例在三个月验证批次。
- `scripts/score_topics.py --input <scoring_inputs.json> --out <本轮目录>`：校验七维分值与理由，计算10分制总分并导出全量Markdown/CSV/JSON；不按分数删行。内容方案未明确则不计算总分。评分依据须先由原文与方案形成，脚本只计算和展示。
- 新批次先依据昨日生成日期计划，不能直接复用旧日期。本轮测了6词：AI辅导、孩子AI、AI学习模式、AI教育、亲子AI、苏格拉底；下轮默认先沿用前5词，最后一词无有效结果，作为低效词停用并记录版本变化，不能静默换词后声称趋势可比。
- 判断与数据分存：`lead_review.json`、`topics.jsonl`、`decisions.csv`。原始采集文件不覆盖，规范化输出可重建。

## 每轮字段、假设与Obsidian入库

2026-10-19确认的规则已纳入执行：以Obsidian账号说明V0.3或更新版本为准；对标分工、单篇来源、系列表现和三个月增长分别维护，缺证据明确“待验证”。时效类型独立于两条内容线：常青科普／历史案例／近期热点／待验证，只有当下升温证据支持时才标近期热点。

内容方案明确后，每条补“具体假设”（观众预计理解或判断什么）与“假设观察线索”，并留复盘位置；素材、合并及未明确方案不编造独立假设。评分强项不等于实际命中，不预设命中门槛，不擅自确定频率或两线比例。保留原题、七维分数与全部取舍理由，宝妈科普不因不是近期热点被天然降分。


用户要求入库时，允许将全量候选存入知识库，不把“入库”理解为已经选定制作。按[入库说明](references/obsidian-library.md)使用原生Bases卡片网格，保持原题、来源、目标、评分、预期命中、制作状态及发布后结果分开。低分及素材保留可见；不填虚假的实际命中结果。已有卡片整篇保留，不覆盖用户选择、状态、正文补充、排期与复盘；重评只进入独立批次档案。新卡强制校验本轮目标、时效、关联、具体假设等现有字段，不按旧编号套目标。导入按作品去重，日期与批次动态生成。

## 边界

90天是期望研究窗口，不是每个接口已经覆盖的事实。近期热点评审与三个月持续增长审计分开交付；缺历史不阻止近期样本评审，也不能把近期样本说成持续增长。

需求反推选题另作后续分支：**需求证据 → 具体场景 → 受阻/痛点 → 可兑现解决方案 → 选题**。目前仅保留需求证据，不自动把评论或需求词当标题。
