# Obsidian选题库与每轮字段契约

当前库：`<EDEN_VAULT>/Eden账号运营/选题库`。
每轮开始先读同级《AI青少年教育账号说明》和`对标账号库/00_对标账号库.md`，再读库内`资料与规则/字段说明.md`、本轮关联卡片的选择和复盘。当前定位V0.3，后续以知识库最新版本为准。项目旧副本及旧研究示范不覆盖用户后来确认的规则。

## 固定执行规则

- 两条线：**AI育儿热点话题／宝妈科普型**。科普线不因非近期热点天然降分；普通家长能理解的AI基础知识本身可以成立，不强加亲子场景或育儿标题。受众仍含爸爸，6—9年级家庭优先范围保留。
- 原题、原视频链接及数据口径保留；另写Eden讲法、具体收获与取舍。先明确内容方案再七维评分，全量展示至少15条有真实来源候选；低分、待核和素材不隐藏。证据不足不编造候选凑数。
- **时效类型**与内容线独立：常青科普／历史案例／近期热点／待验证。近期热点需当下升温证据，不用发布日期或累计点赞替代；常青分类也不是SEO已验证。
- 对标分家长内容、知识解释、新手实践、候选观察；其他作者可作单篇来源。每个关联须说明借鉴角色、边界及代表作品。单篇爆款、系列有效、连续三个月增长分别记录，缺证据标**待验证**。
- 具体假设来自已明确方案：写清“观众预计能理解或判断什么”，另写将来观察什么反馈。没有方案的不编造假设；合并来源不重复计数。
- 评分强项、具体假设、实际效果分开。**不预设命中门槛**；7.5是待校准评分参考线，≥4只是评分强项的展示规则。实际命中要保留支持和不支持证据；无基线或证据不足仍待验证。
- 不擅自确定平台、频率、两线比例、制作时间和排期。不把过去“4基础＋2热点”的建议变为既定要求。

## 新卡输入契约

`score_topics.py`会原样保留额外字段。先在本轮`scoring_inputs.json`中填下面信息，再评分，最后导入`scores.json`。每条需要编辑判断，脚本不按旧ID、标题关键词或作者自动生成。

顶层增加：`research_date`（本轮研究日期YYYY-MM-DD）、`positioning_version`（实际读取的定位版本）、`as_of`（数据实际截至／复用范围）。添加日期由导入参数单独传入。

每条增加`library`对象，键名沿用现有选题库：

```json
{
  "library": {
    "目标": "听懂Agent与聊天的区别",
    "目标格式": "图解＋口播（建议）",
    "时效类型": "常青科普",
    "时效判断依据": "基础能力解释；当下需求和搜索长尾仍待验证",
    "关联对标": ["[[Eden账号运营/对标账号库/Ai 林爻]]"],
    "具体假设": "观众能区分获得建议与调用工具执行任务，并指出人要确认的环节。",
    "假设观察线索": "观察能否用自己的例子说明回答、执行、检查的区别，并记录误解。"
  }
}
```

- 关联对标链接须实际存在；尚未核定可填空列表，并在证据缺口写“关联对标待验证”。不能猜主页、造链接或将每个来源作者提升为核心对标。
- `时效类型=近期热点`另提供`current_heat_evidence`，包含日期、来源、增长/跨账号表现与实际读取范围；脚本只校验有无，证据质量仍由研究判断。
- 已评分方案必须有目标、形式、时效与理由、关联列表、具体假设和观察线索；缺失则整批新增在写入前报错，先补内容再运行。
- 未评分条目需明确`library_state`为待补内容／合并参考／素材备查，不按H08、X04等旧编号推断。不填虚假的假设，脚本保留待明确状态。
- 新卡保留现有字段名与类型，详见 [字段说明](library-fields.md)。研究字段新增不改名；实际发布、选择、复盘字段初始化为空。三个月增长默认待验证，验证结果与证据单独归档后再审阅更新。

## 追加导入与已有卡保护

```sh
python3 .agents/skills/eden-topic-research/scripts/import_obsidian.py --input '<批次>/scores.json' --vault '<EDEN_VAULT>' --added-date YYYY-MM-DD
```

- 按原作URL／已知平台作品ID识别重复；小红书explore与discovery/item及查询参数、YouTube watch与短链接可归一。原链接原样保存。短链未解析时先人工核对，不能声称全部链接格式都能自动去重。
- **已有卡片整篇跳过，字节保持不变**，包括手写正文、原题、讲法、评分、选择、状态、排期、发布链接、复盘和未知自定义属性。改名但选题键或原链接仍在的卡也识别为已有。两个身份字段都被删除时先人工核对，不直接导入。
- 新作品才新增卡片；同名新作品使用选题键后缀，单批同作品多次出现复用同卡。不使用强制覆盖参数。
- 重评和新证据存到`资料与规则/批次/<添加日期>_<输入摘要>/`，含评分输入、来源快照、本批选题链接。跨日或同日不同输入独立归档，相同输入重复运行不覆盖。
- 现有看板、入口索引、字段说明与规则不重写；新卡自动出现在Bases中，本批Markdown索引放批次页。
- 如用户另行要求把重评应用到旧卡：先保留旧评分和备份、列出**研究字段**差异，再仅更新指定字段。选择、状态、正文中用户补充和全部复盘字段属于用户记录，不用导入默认值覆盖；刚读后的用户新编辑也要合并保留。普通研究运行只归档，不自动应用。

## 验收

核对本轮新增／复用数量、原题与来源、未知分空值、日期、全部现行字段和实际结果为空。用隔离库模拟用户已选／已发布并写了复盘、重命名、链接参数改变、同名不同作品、同日多批与跨日运行，确认旧文件字节不变且新作品不遗漏。正式重复测试用隔离副本，不污染真实库。

查看Obsidian实际显示，库文件保存不等于其他设备同步完成。规则更新时同步本参考和生成模板；不能只改SKILL.md而让新卡仍用旧字段。
