# Eden 选题采集与筛选流程 v0.6

用户2026-10-19最新要求：两条线为“AI育儿热点话题”“宝妈科普型”；内容方案明确后评分、全量展示，至少15条评分候选；低分不能隐藏。[评分规则](scoring.md)取代旧版15进5及评分资格门槛。

2026-10-19。来源：用户本轮明确要求、账号说明V0.2、PPT两页截图。下列数量门槛、权重和运行频率为本项目初始设计，需经实跑校准，不是PPT原公式或经过验证的行业标准。

## 1. 验收的对象

不是“生成了5个标题”，而是“多个数据源中与定位相关的话题，能重复被发现、有可追溯证据，且能解释为什么保留或排除”。流程为：

定位版本 → 第三方榜单＋对标问题检索＋B站/YouTube采集 → 原文核验 → 去重 → 内容方案明确 → 七维评分 → 全量展示至少15条候选 → 用户选择。错配和低分保留理由，不按分数隐藏。90天审计另列，不混为评分事实。

PPT要求近3个月、约15选题、去重并结合定位筛5个、人工选择、附原链接。本轮用户进一步要求持续增长。PPT的示例受众“怕代码的文科生”、示例对标及其差异点不属于Eden的新账号，不能直接复制。PPT左侧5分维度与右侧7.5总分的换算未说明，下文单独定义试行算法。

## 2. 把定位变成检索与筛选条件

### 定位合同（每轮从真源更新）

- 服务谁：普通家长，优先6—9年级家庭；普遍性问题不强制限定年级。
- 提供什么：听懂与家庭有关的AI知识和变化；理解具体用途；形成是否值得尝试、如何判断的依据。
- 能拿什么作证：公开可靠材料、真实操作与作品、真实家庭反馈。三者按需要使用，不要求每条都有工具演示。
- 不冒充什么：教育专家资历、真实亲子经历、未经验证的学习收益。
- 非主要需求：成人办公、开发者工程细节、创业变现。一般育儿若AI仅是标签，也不进入主库。

### 查询词表：从问题来，不从大类来

先建立“家长问题—AI对象／机制—适龄场景—证据来源”的映射。每条词记录来自定位、对标原文、真实追问还是编辑假设。

检索词示例仅用于测试召回，不是新选题推荐：

| 需求入口 | 初始检索词例 | 必须排除的误命中 |
|---|---|---|
| 听懂变化 | AI时代孩子学什么、孩子使用AI、AI学习模式 | AI公司招聘、成人转行；只有AI标签的一般教育内容 |
| 获得判断 | AI作业思考、AI辅导孩子、AI讲题错误 | 单纯硬件带货、与学习无关的AI段子 |
| 看见可能 | 孩子AI创作、学生AI项目、亲子AI作品 | 成人接单教程、与孩子参与无关的动画秀 |

采用三条采集路径：问题／场景关键词全站搜索；已知对标和相关真实作品扩作者；相关分类榜单发现池。相似账号接口本轮未通过语义验收，暂不采用。榜单和相似推荐只给线索，仍过语义筛选。B站／YouTube补机制、案例和源头；海外热度不能直接当中国家长需求。

每轮固定词表、窗口、排序、页数和采样量，记录query_id。新增词单列新版本；不能因为搜不到就不断换词，最后把搜索偏差说成增长。

## 3. 数据源先验收，再扩大采集

每个数据源用小样确认：成功返回、目标日期被接受、实际覆盖范围、稳定作品／账号ID、原文链接、指标含义、更新时间、历史增量字段是否存在。保留脱敏响应，密钥不入库。

数据源状态仅用：文档已核对／代码已核对／接口小样通过／跨期验收通过／受限或失败。

至少对最旧期、中间期、最新期核对实际响应日期。若服务仅有30天，不能用三个近30天请求替代90天，也不能以脚本接受days=90认定数据齐全。

首次90天数据获取路径：

1. 小红书账号层：候选月榜／涨粉榜查询三个完整自然月，核对统计周期，用于发现多个月增长的账号。2026-10-19时可拟查7、8、9月，实际月份以接口定义与返回为准。
2. 小红书作品层：灰豚历史范围／导出能力需小样验证；原平台历史作品可辅助回溯，但当前计数不补成历史计数。红狐已实测支持明确日期的前两个月历史作品取样，逐条检查日期，不能只重复最近30天。
3. B站：现有搜索Skill支持90天发布时间过滤；仍需核对返回时间、翻页与跨期样本。它不提供90天历史曲线。
4. YouTube：通过可用的agent-reach读取搜索与字幕，逐条核对发布日期和内容；没有历史曲线时仅算跨期作品证据。
5. 拿不到前两期就标覆盖缺口。可先建近期观察库，并从现在保存快照；不得把90天验证写成完成。

商业笔记、品牌自宣、搬运、系列复制、异常促销单列。只收录热门的数据源会遗漏小账号和低互动作品，因此需补原账号同期普通作品作为基线；没有基线时不计算“相对账号爆款”。

## 4. 跨账号与话题聚类

以原作品ID去重，再按底层事件／产品发布／同一素材去重。转载到多个平台或多个账号，不等于多个独立需求证据。

话题簇键：目标问题＋核心对象／机制＋内容承诺。标题不同但解决同一问题可归一簇；都叫“AI教育”不构成同题。

保留三种账号角色：同受众的内容参考、不同账号的增长验证、跨领域的机制／表达参考。Evan和Coco是定位参照，不是唯一候选来源；表达参考账号的观众不能被自动算成家长。

首轮目标寻找约10—20个相关账号，覆盖不同体量；这是采样目标，不是必须凑满。应优先寻找不同话题；本轮先收约15条真实线索，再去重成话题，须分别报告线索数和独立话题数，不能把同题多作品称15个独立选题。单个账号贡献的独立支持样本原则上不超过某话题的一半；不足时标“依赖单一账号”。

## 5. 适配评估：热度不能补偿不匹配，但记录仍展示

每条证据卡回答以下四问，并给原文／评论／定位段落依据：

1. **家长价值**：家长看完具体理解什么、能判断什么或看见什么可能？仅“很火”“很震撼”不够。
2. **AI关联**：AI机制或变化与学习／成长存在实质关系，还是只是生成手段／标签？
3. **迁移距离**：保留原话题的核心问题和内容承诺后是否仍适配？是否必须换受众、加虚构孩子情境、强塞AI才能成立？
4. **兑现依据**：Eden能通过材料、操作或真实反馈兑现承诺吗？不依赖不存在的身份、资源或夸大结果。

分类：

- **直接适配**：四问有具体依据；允许进入持续性评估。
- **相邻待验证**：原话题家庭关联/年龄本身尚不清楚；进待补证库。直接适配也可能尚缺制作实测，要单列“制作就绪度”；不能因为尚未拍片测试便把明确适配话题一律退回。
- **仅素材／表达参考**：有形式或机制可借鉴，但原需求不属于目标人群；不继承其热度。
- **排除**：无家庭价值、无实质AI关联、核心需求已换掉或无法真实兑现。留排除原因，不硬改标题救回来。

受众证据优先读评论中的具体家庭情境、提问和使用反馈；不凭昵称、头像、性别猜家长。普遍知识解释可以符合定位；HD依科普线理解需求证据评估，不凭定位相关性直接给高分，也不因来源非家长账号一律压到2分。

## 6. 三个月持续性与增长：两个不同问题

统一上海时间，滚动窗口用昨日截止的90个完整日期，切为三个不重叠30天块；自然月榜另外保存，不与30天块混算。2026-10-19的作品窗口为7/21—8/19、8/20—9/18、9/19—10/18。

### 持续性

每块记录：独立作品数、独立作者数、适配作品数、原文可核验数、相关需求反馈、数据源覆盖。试行“跨期重复成立”的最低证据为：三个块均有独立相关作品，总计至少3个独立账号、6条作品，任一块不由同一转载事件垄断。未达标不等于没需求，只是证据不足。

### 增长

分别回答，不混为一个增长分：

- 账号增长：同一账号每期新增粉丝、点赞、收藏等；上榜之外的月份是缺失，不是0。三期新增均正为持续净增长；新增规模扩大才是加速。不能推出具体话题贡献。
- 话题扩散：在固定检索与采样口径下，每期独立创作者和相关作品是否增多；若只有TopN搜索样本，只能写“样本内扩散迹象”，不能写全站规模增长。
- 内容吸引力：优先比较同平台、同发布年龄（例如发布后7天）的作品互动，或同一组作品连续快照的增量／天。收藏、评论、分享分列，不混加不同平台指标。

当前累计赞高、旧作品多、多个时期都有作品，都不能单独证明持续增长。仅有正增量说明仍在增长，不意味着增长速度上升。

只有三期均有可比、可追溯的时间序列，且变化不是由换词、换样本量、换平台、单一大号或广告推动，才可写相应维度的“持续增长证据”；要注明指标和样本范围，不能笼统称趋势已验证。

给每簇两个标签：持续性＝未覆盖／跨期有样本／跨期重复成立；增长＝无历史增量／样本扩散迹象／可比增量支持，并附依据。稳态常青、近期突发和增长话题分库；用户此次要找的持续增长池不混入只有近期爆点的内容。

## 7. PPT七维评估：先明确内容，再评分并全量排序

统一使用[评分v0.3](scoring.md)，不再保留与其冲突的旧锚点。科普需求不以近期热点或增长为条件，跨受众知识先例有效但不能继承家长需求规模；证据置信度、制作准备度与选题潜力分分列。7.5为待校准参考线。先执行[高表现查漏和来源分类](recall-and-provenance.md)，再评分；不得用先筛15条熟悉作品代替全池查漏。

## 8. 持久保存与重复运行

每次运行在项目`选题研究/运行记录/<上海日期-批次>/`保存：

- `manifest.json`：定位版本、规则版本、词表、窗口、工具版本、采样方案、查询成功／失败、覆盖缺口、请求与实际返回窗口。
- `sources.jsonl`：平台、作品ID、作者ID、原题、完整URL、发布时间、来源更新时间、采集时间、原指标字符串及明确口径、广告标记、内容核验范围、证据路径。
- `snapshots.jsonl`：追加记录相同作品在不同时点的指标，不覆盖旧值；0与缺失分别保存；1.2万等近似值保留精度，不伪造精确差值。
- `topics.jsonl`：话题ID、核心问题、独立证据ID、每期覆盖、适配四问、分类、持续性／增长标签、七维得分及依据、待补证项。
- `decisions.csv`：话题ID、采纳／拒绝／暂缓、用户理由、改动的规则或关键词、适用范围、日期。

建议操作节奏：首次建立90天基线；后续每周用固定词表补新作品、复查固定样本；每月比较三个时间块并调整规则；自有内容按发布48小时、7天、30天复盘。这里只定义运行方式，不自动建立订阅。选题证据库可以持续更新，是否定时需用户另行指定。

失败处理：保留已有证据；按数据源规定的次数停止重试，转可用渠道并标来源变化；不以编造常青内容填满实时榜。数据口径变化后重新建可比区间。

## 9. 怎样验收“跑正确”

方法校准：旧错配样本能被拦截；高热度不抵消低FIT；单账号不通过多账号验证；30天数据不被标90天；单次快照不被标增长。

数据小样：最旧／中间／最新三期的日期、来源、实际字段、账户权限均核实，且接口失败不被空列表掩盖。保留来源覆盖表。

完整批次：每条候选有来源、内容范围、七维分数/缺项及理由；至少15条评分候选目标通过补研究满足，错配和低分仍可见；不得只交前5。数据确实不足则报告实际数与缺口，不虚构补齐。跨期增长是否通过另行验收。

连续运行：至少两个独立批次采用相同口径可复现；统计直接适配率、错配来源、候选采纳率、无效调用及成本。初始没有基线，不承诺具体达标率。用户反馈优先修正查询／过滤条件，避免只改标题。

发布效果：另用自有账号观看、关注、目标家长反馈验收，不能用第三方热度代替。此版本通过方法回放不代表已通过数据、连续运行或内容效果验收。
