# 公众号 AI 内容生产

把一个明确的读者问题，变成有证据、有图片、可在公众号草稿箱验收的文章。也支持只研究、只写稿、只排版或恢复补传：按用户要求进入对应阶段，不强制重跑全流程。

## 开始前

1. 读取当前项目的账号说明、用户最新反馈、任务范围及运行状态。沿用用户已确定的选题、人群和风格；运营已给题卡时，直接创作，不重新做账号战略。
2. 确定本次模式：`write`（正文）、`package`（含图本地包）、`draft`（草稿箱）或 `resume`（补缺失阶段）。用户要求整套公众号产出时以 `draft` 为终点；没有上传工具或权限时保留本地包，准确报告缺项。
3. 读取 [创作与证据规则](references/editorial.md)。首次配置账号时参考 [账号配置](references/account-profile.md)；每次写稿读取本地配置，不能把库里其他平台的人群、栏目或选题字段自动套进来。
4. 有既定自动任务时先检查当日记录，只接续任务。Skill 本身不是调度器；只有用户要求定时运行时才配置现有调度器，不重复创建任务。

## 生产顺序

### 1. 选题和证据

写下读者、具体问题、中心判断、栏目与本篇新增价值。检查近期记录，同一工具可连续深挖，但必须增加场景、步骤、验证或新证据。

先读已有研究，再查缺失的一手来源。市场参考文章只用于理解标题、解释方式和视觉，不能证明产品能力或商业效果。同一次研究请求只查询一次，结果由写作、标题、封面共享。记录真实来源、发布时间、检索时间、版本和不确定项；无法核验就缩小结论或更换选题。

### 2. 完整初稿和标题

主执行者保留完整材料，完成全文和候选标题。按读者的问题组织解释，不写工具清单式堆砌。实操稿必须交代输入、AI 动作、人工验收、最终营销产物及效果观察方法。行业稿区分新闻事实、分析判断和建议；产品稿区分可用功能、开发中能力与效果愿景。

### 3. 编辑与终审

依次保存 `draft.md → edited.md → article.md`。先做中文编辑，再做去模板腔、事实边界和假经历审查。保存具体前后修改与理由到 `humanizer_report.md`；没有必要修改也须记录检查结果，不能伪造改稿。

可用的原 Skill 按 [能力适配表](references/skill-map.md) 调用。没有原 Skill 时，执行本包明确写出的规则，并记录 `method_applied`，不得称“已调用该 Skill”。外部研究、图片、检测和上传能力无法以文字模拟。

### 4. 全文检测

最终标题、摘要、正文、图注和可复制来源网址一起检查。使用已配置的第三方敏感词服务时只提交准备公开的文字；按该服务真实上限分片，保存完整覆盖记录和文本哈希。相同版本复用结果；改稿后重检变更部分并更新覆盖记录。

命中项逐条人工判断；第三方词表不是微信官方审核。服务不可用就记录失败和人工检查，不虚报远端检测通过。账号配置要求远端通过时，此阶段未通过不能称整套交付完成。

### 5. 封面与内文图

先从终稿提炼每张图的作用，再分析构图、确定提示词、生成或复用。遵循用户已认可的视觉方向，不每日重复征询。可用 imagegen 生成新图；每张最终资产必须实际查看，检查手部、文字、主体、裁切和文章相关性。图片数量服从解释需要。

不得将概念图伪装成真实产品截图、客户照片或新闻现场。计划中标明生成/复用来源、文件、用途、验收意见。只保存提示词不算配图完成。

### 6. 微信排版与本地校验

按 [交付包和草稿协议](references/delivery.md) 生成 Markdown、HTML、manifest、证据、审校、图片计划和实际 Skill 使用记录。正文采用适合手机阅读的短段落和内联样式；来源另附可复制网址，不能只依赖超链接。

运行本包的机械校验：

```sh
python3 <本Skill目录>/scripts/package_guard.py validate <交付目录>
```

它检查文件、路径、HTML 图片和来源网址，不替代事实、文字、视觉或账号权限审核。

### 7. 创建草稿并读回

使用已经配置并验证的公众号连接器或 API 助手；读取其说明与帮助，不能假定机器上存在某个绝对路径。先检查凭据可用性，再完成包校验和草稿箱去重。凭据只从本机私有配置或环境变量读取，不写进交付包、日志、聊天或 GitHub。

开始上传前写 `upload_attempt.json`；取得真实响应后保存 `upload_result.json`。随后读取该草稿，核验文章顺序、标题、封面、全部内文图、可见正文及来源网址。兼容微信图片 `src`/`data-src` 和可确认的尺寸改写；不同图片资产不能宽松判等。

```sh
python3 <本Skill目录>/scripts/package_guard.py verify <交付目录>
```

校验读取 `remote_draft.json` 与标准化的 `upload_result.json`；适配格式见交付协议。读回不符时修复原草稿，再核验，不能新建一份来掩盖问题。只有所有要求的文章和审核均完成，且真实草稿读回通过，才能报告整套完成。

### 8. 恢复与交付

每完成一个阶段保存检查点。外部失败最多自动重试两次；上传超时或结果不明时不自动重试创建。先运行 `package_guard.py resume <交付目录>`，再按 [恢复规则](references/delivery.md#恢复规则) 查远端。未确认的旧尝试不能当作“没上传”。

向用户报告篇数、标题、本地路径、草稿状态及具体待审点。仅写作请求以成稿为交付终点；草稿请求不能以“生成了 HTML”冒充完成。正式发布、群发或定时发布由用户另行明确授权。
